# AFTER CL TO MOON — 클럽 웹사이트

석촌호수 근처 사설 볼더링 클럽 **AFTER CL TO MOON**의 모바일 우선 웹사이트(PWA)입니다.
멤버는 일정과 회원권을 확인하고 이벤트를 제안합니다. 운영진은 **Google Sheets 하나**로 일정·회원·회비를 관리하고, 입금만 확인·승인하면 회원권 기간과 알림이 자동으로 처리됩니다.

- **v0.1** 월간 캘린더(멤버 등록기간 / 이벤트 신청기간 / 이벤트), 이벤트 목록·상세, 이벤트 제안서
- **v0.2** Google 로그인, 회원권(기간 자동 계산·연장), 모임통장 입금 승인, 거래내역 엑셀 매칭, 운영진 화면, PWA 설치, 웹 푸시 알림

---

## 구조

```
브라우저(PWA) ──▶ Next.js 16 (Vercel) ──▶ Apps Script 웹앱 ──▶ Google Sheets (단일 스프레드시트)
                     │  서버에서만 시트 접근        │  GET: 공개 일정만
                     │  로그인·권한 매 요청 검증    │  POST read/commit: 비밀키 + LockService 잠금
                     └─ Vercel Cron / Apps Script 트리거 ──▶ /api/cron/notifications ──▶ Web Push
```

- **정본은 Google Sheets뿐입니다.** 별도 DB 없이, 웹은 Apps Script 웹앱을 통해서만 시트를 읽고 씁니다.
- **쓰기는 모두 `commit` 하나로 처리합니다.** Apps Script가 `LockService` 잠금 안에서 ① 같은 요청의 재시도인지 확인(AuditLog의 `commit_id`)하고 ② 전제조건을 실시간 시트로 다시 검증한 뒤 ③ 쓰기 전체를 검사하고 ④ 순서대로 씁니다. 이 구조로 같은 입금의 중복 승인, 동시 승인으로 인한 기간 겹침, 네트워크 재시도로 인한 중복 반영을 막습니다. 같은 규칙이 `src/server/store/commit.ts`(로컬·테스트용)와 `apps-script/Code.gs`(운영용)에 함께 구현되어 있습니다.
- **공개 API에는 공개 일정만 나갑니다.** `visibility=public` 이고 `status`가 published/closed/canceled인 이벤트와 공개 열만 내보냅니다. 회원·회비·제안·구독 정보는 비밀키가 있는 서버 요청으로만 읽을 수 있습니다.

| 폴더 | 내용 |
|---|---|
| `src/app` | 페이지: `/`, `/events`, `/host`, `/login`, `/me`, `/notifications`, `/admin/*`, `/offline`, API 라우트 |
| `src/lib` | 날짜(Asia/Seoul), 이벤트 상태, 캘린더 배치, **회원권 기간 엔진**(`membership.ts`) |
| `src/server/store` | 시트 스키마, commit 규칙, Apps Script 클라이언트, 데모용 메모리 저장소 |
| `src/server/domain` | 승인·반려·환불·수정 규칙, 알림 스케줄, 거래내역 파서·매칭 |
| `src/server/auth` | Google OIDC(PKCE), 서명 세션 쿠키, 권한 확인 |
| `apps-script/Code.gs` | 시트 게이트웨이(Apps Script 편집기에 붙여넣기) |
| `public/sw.js` | 서비스 워커(오프라인 화면, 푸시) |

## 로컬에서 실행

```bash
npm install
npm run dev        # http://localhost:3000
```

환경변수가 없으면 **데모 모드**로 실행됩니다. 예시 일정과 예시 회원이 서버 메모리에 만들어지고, `/login`에서 데모 계정(운영진, 이용 중 회원, 곧 만료 회원, 입금 대기 신청자, 미등록 계정)을 골라 모든 화면을 확인할 수 있습니다.

```bash
npm test           # 단위 테스트(기간 계산, 승인 동시성, 거래내역 파서, 알림 스케줄 등)
npm run lint
npm run typecheck
npm run build
```

> **시트를 연결하기 전에는 배포된 사이트도 자동으로 데모 모드**로 동작합니다. 상단에 데모 배너가 뜨고, 로그인 화면에서 데모 계정(운영진 포함)을 골라 회원·관리 화면을 둘러볼 수 있습니다. 데모 데이터는 서버 메모리에만 있어 수시로 초기화되고, 제안서에 적은 연락처는 저장하지 않습니다. `CLUB_API_URL`과 `CLUB_API_SECRET`을 넣으면 데모는 자동으로 꺼집니다. 시트 연결 전에 회원 기능을 아예 숨기려면 `DEMO_MODE=false`로 설정하세요.

## 배포 순서

### 1. 스프레드시트와 Apps Script

1. Google 드라이브에서 새 스프레드시트를 만듭니다. 운영진에게만 편집 권한을 공유합니다.
2. **확장 프로그램 → Apps Script**를 열고 `apps-script/Code.gs` 내용을 붙여넣습니다. 프로젝트 설정에서 시간대를 `Asia/Seoul`로 맞춥니다(또는 `appsscript.json` 내용을 사용합니다).
3. 편집기에서 **`setupSheets`** 함수를 한 번 실행합니다(처음에 권한 승인 필요). 탭 13개, 머리글, 드롭다운, 기본 회원권 상품 3종, 설정 값이 만들어지고 시트 시간대가 서울로 바뀝니다. 다시 실행해도 기존 데이터는 그대로 두고 빠진 열만 추가합니다.
   > **Apps Script를 아직 실행할 수 없다면** `apps-script/after-cl-to-moon-sheet-template.xlsx`로 같은 시트 구조를 만들 수 있습니다.
   > Google Sheets에서 **파일 → 가져오기 → 업로드 → 스프레드시트 바꾸기**로 가져온 뒤 **파일 → 설정 → 시간대**를 `(GMT+09:00) 서울`로 맞추고, Settings 탭의 `sheet_url`에 시트 주소를 붙여넣으세요.
   > 나중에 Apps Script에서 `setupSheets`를 실행해도 기존 데이터는 그대로 두므로 안전합니다.
4. **프로젝트 설정 → 스크립트 속성**에 다음 값을 추가합니다.
   - `PROPOSAL_SECRET`: 긴 무작위 문자열. Vercel의 `CLUB_API_SECRET`과 같은 값입니다.
   - `SITE_URL`: `https://<사이트 주소>` (15분 알림 트리거를 쓸 때)
   - `CRON_SECRET`: Vercel의 `CRON_SECRET`과 같은 값 (15분 알림 트리거를 쓸 때)
5. **배포 → 새 배포 → 웹 앱**으로 배포합니다. 실행 계정은 **나**, 액세스 권한은 **모든 사용자**로 설정하고, 발급된 `/exec` URL을 `CLUB_API_URL`로 씁니다.
   *코드를 고친 뒤에는 배포 관리 → 수정 → 새 버전으로 다시 배포해야 하며, URL은 그대로 유지됩니다.*
6. (선택) 편집기에서 **`installTick`**을 실행하면 15분마다 알림 스케줄러가 호출됩니다. 이벤트 신청 시작·마감 알림이 더 제때 나갑니다.
7. **Settings 탭**에 모임통장 계좌번호와 예금주를 입력합니다. 회원의 입금 안내 화면에 표시됩니다.

### 2. Google 로그인

1. [Google Cloud Console](https://console.cloud.google.com/) → API 및 서비스 → **OAuth 동의 화면**을 구성합니다(외부, 범위 `openid email profile`).
2. **사용자 인증 정보 → OAuth 클라이언트 ID**를 만듭니다. 유형은 **웹 애플리케이션**입니다.
   - 승인된 리디렉션 URI: `https://<사이트 주소>/api/auth/callback/google` (로컬 테스트용으로 `http://localhost:3000/api/auth/callback/google`도 추가)
3. 클라이언트 ID와 비밀번호를 `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`에 넣습니다.

### 3. 웹 푸시 키

```bash
npx web-push generate-vapid-keys
```
공개 키는 `NEXT_PUBLIC_VAPID_PUBLIC_KEY`, 개인 키는 `VAPID_PRIVATE_KEY`에 넣습니다. `VAPID_SUBJECT`에는 `mailto:운영진메일`을 씁니다. 키를 바꾸면 기존 구독이 모두 무효가 되니 한 번 정하면 유지합니다.

### 4. Vercel

GitHub 저장소를 Vercel 프로젝트로 가져온 뒤, **Settings → Environment Variables**에 `.env.example`의 값을 설정하고 배포합니다.

| 변수 | 필수 | 설명 |
|---|---|---|
| `CLUB_API_URL` | ✓ | Apps Script 웹앱 `/exec` URL |
| `CLUB_API_SECRET` | ✓ | 스크립트 속성 `PROPOSAL_SECRET`과 같은 값 |
| `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET` | ✓ | Google 로그인 |
| `AUTH_SECRET` | ✓ | 32자 이상 무작위 문자열(세션 서명). 데모 모드에서는 없어도 동작하지만, 시트를 연결하면 필수 |
| `NEXT_PUBLIC_VAPID_PUBLIC_KEY` / `VAPID_PRIVATE_KEY` / `VAPID_SUBJECT` | 푸시 | 없으면 앱 안 알림 목록만 동작 |
| `CRON_SECRET` | ✓ | 스케줄러 호출 인증(Vercel Cron이 자동으로 첨부) |
| `NEXT_PUBLIC_SITE_URL` | | 공유 미리보기용 주소(기본값: Vercel 운영 도메인) |
| `DEMO_MODE` | | 시트가 없으면 기본이 데모 모드. `false`로 두면 시트 연결 전까지 회원 기능을 "준비 중"으로 숨김 |

`vercel.json`의 Cron이 **매일 09:00(KST)**에 `/api/cron/notifications`를 호출합니다. Hobby 요금제의 Cron은 하루 한 번만 실행되므로, 더 촘촘한 알림이 필요하면 1-6의 Apps Script 트리거를 함께 씁니다. 두 쪽이 겹쳐 실행돼도 중복 발송되지 않습니다.

### 5. 첫 운영진 지정

Members 탭에 직접 한 줄을 추가합니다.

| member_id | name | email | depositor_name | role | status |
|---|---|---|---|---|---|
| M-ADMIN-1 | 이름 | 운영진의 Google 메일 | 입금자명 | admin | active |

이후 운영진 권한은 웹의 **ADMIN → 회원 → 상세**에서 admin만 바꿀 수 있습니다.

## 운영 가이드

### 일정 (Events / Enrollment 탭)

- `status`: `draft`(비공개 작성 중) → `published`(공개) → `closed`(정원 마감 등 수동 마감) / `canceled`(취소 표시)
- `visibility`: `public`만 웹에 노출됩니다. `private`는 캘린더에 나오지 않습니다.
- 날짜는 셀에 날짜·시간으로 입력합니다(시트 시간대는 서울). **날짜만 입력**하면 다음처럼 해석합니다.
  - `start_at`만 날짜 → 종일 이벤트
  - `registration_close`가 날짜만 → 그날 23:59까지 신청
  - `end_at`이 없으면 시작일 하루 동안 진행
- 신청 상태는 날짜로 자동 계산됩니다: COMING SOON(신청 전) · OPEN · CLOSED · FINISHED · CANCELED.
  - `registration_close`가 없으면 이벤트 시작 시각에 마감됩니다.
  - `registration_open`이 있어야 캘린더에 신청기간 점선이 그려집니다.
- `short_title`은 캘린더 칸에 들어가는 짧은 이름, `notes`는 준비물·안내, `public_fee`는 **공지용 참가비**입니다(제안자의 희망 금액과 별개).
- 시트를 고치면 1~2분 안에 웹에 반영됩니다.

### 회원권과 회비

1. 회원이 로그인해 MY에서 회원권을 신청하면 Payments에 `pending`으로 기록되고, 회원에게 모임통장 입금 안내가 표시됩니다. **승인 전에는 회원권이 생기지 않습니다.**
   - **첫 등록에는 가입비가 붙습니다** (기본 100,000원, Settings 탭 `joining_fee`로 변경, 0이면 받지 않음). 회원권 금액과 합친 금액을 한 번에 입금하도록 안내하고, Payments의 `amount`에는 합계가, `joining_fee`에는 가입비가 기록됩니다.
   - "첫 등록"은 한 번도 승인된 적이 없는 경우입니다. 사이트 이전부터 활동한 기존 회원은 Members 탭에 `joined_at`(가입일)만 적어 두면 가입비가 청구되지 않습니다.
2. 운영진은 모임통장 앱에서 입금을 확인한 뒤 **ADMIN → 입금 확인**에서 승인합니다. 입금일과 이용 시작일은 따로 지정할 수 있습니다.
3. 승인하는 순간 Memberships에 기간이 생성되고, 회원 상태가 active로 바뀌며, 회원에게 알림이 갑니다.

**기간 계산** (민법 제160조 방식, Asia/Seoul 기준):
- 시작일과 만료일을 모두 포함합니다. 예: 2026-11-11에 1개월 시작 → **2026-12-10** 종료
- 만기 달에 같은 날짜가 없으면 그 달 말일에 끝납니다. 예: 01-31 시작 1개월 → 02-28(윤년은 02-29)
- 총 기간 = `duration_months + bonus_months` (6개월권은 7개월, 12개월권은 14개월)
- **연장**: 남은 회원권이 있으면 마지막 만료일 다음 날부터 이어지므로 남은 기간이 보존됩니다. 이미 만료됐으면 승인일(또는 회원의 희망 시작일, 운영진 지정일)부터 다시 시작합니다.

**수정·취소·환불**은 모두 AuditLog에 누가 언제 무엇을 바꿨는지(변경 전/후) 남습니다.
- 승인 취소: 회원권은 `canceled`로 남기고 입금은 다시 `pending`으로 돌립니다(올바른 조건으로 재승인 가능).
- 환불: 입금과 회원권을 `refunded`로 바꿉니다.
- 회원권 기간 수정: 회원 상세에서 변경 사유를 함께 입력합니다. 같은 회원의 다른 회원권과 겹치면 저장되지 않습니다.

### 동의서

동의서는 크루의 Google 설문으로 받습니다. 응답은 Google Forms에 쌓이고, 사이트는 안내와 확인 기록만 맡습니다.

- **일일 이용 동의서**: 회원이 아닌 방문자가 방문하는 날마다 작성합니다. `/consent` 페이지에 모아 두었으니 카톡이나 출입구 QR로 공유하세요. 홈, 이벤트 상세, 푸터에서도 연결됩니다.
- **회원 등록 동의서**: 처음 회원권을 신청할 때 "Step 1"로 안내하고, "제출했어요"에 체크해야 신청됩니다. 체크한 시각은 Members 탭의 `member_consent_at`에 기록되고 AuditLog에도 남습니다. 사이트 이전에 등록한 기존 회원은 MY 화면에서 한 번 확인하면 됩니다.
- 운영진은 입금 승인 카드의 **동의서 ✓ / 동의서 미확인** 표시를 보고, 필요하면 Google Forms 응답에서 성함·연락처로 대조합니다(설문이 이메일을 수집하지 않아 자동 대조는 하지 않습니다).
- 설문을 새로 만들면 Settings 탭의 `consent_daily_url`, `consent_member_url`만 바꾸면 됩니다.

### 회계 (ADMIN → 회계)

클럽의 돈 흐름을 한곳에서 봅니다. 수입은 두 군데에서 모입니다.
- **회비·가입비**: 입금을 승인하면 자동으로 수입에 잡힙니다(Payments 기준이라 따로 적지 않습니다). 환불되거나 승인이 취소된 입금은 빠집니다.
- **그 밖의 모든 것**: 출자금, 일일 이용료, 이벤트 참가비, 그리고 모든 지출은 **Ledger 탭**에 기록합니다. 화면의 "기록 추가"를 쓰거나 시트에 직접 적어도 됩니다.

화면에서 보는 것:
- 지금 남은 돈, 총 수입, 총 지출, 보증금(돌려받을 돈)
- 월별 수입·지출과 월말 잔액, 항목별 지출·수입 순위, 출자자별 합계
- 기간·수입/지출 필터, CSV 내려받기(엑셀에서 한글이 깨지지 않게 BOM 포함)

기록은 지우지 않고 **무효 처리**합니다. 수정과 무효 처리에는 사유가 필요하고, 모두 AuditLog에 남습니다.

**기존 회비 사용 내역 옮기기:** `private/ledger-import.xlsx`(Git 제외)에 기존 시트를 Ledger 형식으로 바꿔 두었습니다. 잔액이 원본의 차액과 같은지 확인했습니다. 실데이터 시트의 Ledger 탭 2행부터 그대로 붙여넣으면 됩니다. 출자금은 원본에 날짜가 없어 첫 지출일로 넣었고, "계약비"는 보증금의 일부(계약금)로 분류했으니 확인해 주세요.

### 거래내역 엑셀 매칭 (ADMIN → 거래내역)

카카오뱅크 앱에서 모임통장 거래내역을 엑셀로 내려받아 올리면, 입금만 골라 신청 내역과 비교합니다.
- **일치**: 입금자명과 금액이 한 건과 정확히 맞음 → 확인 후 승인
- **확인 필요**: 동명이인(같은 이름·금액 여러 건), 부분 입금·금액 다름, 대리 입금(금액만 같음)
- **반영됨**: 이미 승인에 쓰인 거래. 같은 파일을 다시 올려도 두 번 반영되지 않습니다(거래 키 = 거래일시·금액·잔액·입금자명의 해시).
- 파일은 서버 메모리에서 읽기만 하고 **저장하지 않습니다.**

> ⚠️ 파서는 열 이름(거래일시·거래금액/입금액·구분·내용·거래 후 잔액 등)으로 머리글을 찾도록 만들었지만, **실제 모임통장 내보내기 파일로는 아직 검증하지 않았습니다.** 개인정보를 가린 실제 파일 한 개로 확인한 뒤 필요하면 열 이름을 보완해야 합니다(`src/server/domain/bank.ts`의 `ALIASES`).

## 보안과 개인정보

- 브라우저는 시트에 직접 접근하지 않습니다. 모든 읽기·쓰기는 서버에서 비밀키로 Apps Script를 호출합니다.
- 로그인은 Google OIDC(PKCE·state·nonce 검증)로 하고, 세션은 서명된 httpOnly 쿠키에 저장합니다. **권한(member/operator/admin)은 매 요청 Members 시트로 다시 확인하므로**, 시트에서 권한을 바꾸면 즉시 적용됩니다.
- 회원 화면은 로그인한 본인 데이터만 조회합니다(URL에 회원 ID를 받지 않음). 운영진이 아니면 관리 화면은 404로 보입니다.
- 웹에서 시트에 쓰는 모든 텍스트는 일반 텍스트로 저장되어 수식이나 숫자로 해석되지 않습니다.
- 서비스 워커는 페이지를 캐시하지 않아, 공용 기기에서 다른 사람의 회원 정보가 남지 않습니다.
- 데모 로그인은 시트가 연결되면 자동으로 꺼집니다.

## 알려진 제한

- Notifications·AuditLog 탭은 계속 쌓입니다. 1년에 한 번 정도 오래된 행을 다른 시트로 옮겨 보관하는 것을 권장합니다.
- Apps Script 호출은 0.5~2초가 걸립니다. 회원 화면은 30초 서버 캐시로 보완하고, 운영진 화면과 모든 쓰기는 항상 실시간 시트를 기준으로 합니다.
- 접근 권한이 없는 관리 화면은 404 화면을 보여주지만, 스트리밍 렌더링 특성상 HTTP 상태 코드는 200입니다(내용은 노출되지 않음).
